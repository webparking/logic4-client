# Contributing

Bug reports and pull requests are welcome. This page explains how the package is built, generated, tested and released.

The client follows Logic4's API documentation. An issue for a missing endpoint is in scope when Logic4 already documents that endpoint; requests for new Logic4 functionality belong with Logic4 itself.

## Development environment

The repository ships a Docker workspace with PHP, Composer and pcov. The `Makefile` wraps the common commands:

```bash
make start      # build the image, start the container and install dependencies
make cmd        # open a shell in the workspace
make test       # run PHPUnit
make analyze    # run PHPStan and PHP CS Fixer
make test-all   # run the full quality gate, see below
make stop
```

Without Docker, any PHP 8.3 or newer with Composer works:

```bash
composer install
composer test
```

## Quality gate

`composer test` runs everything CI runs, in this order:

1. `composer phpstan`: PHPStan at level 8 on `src/` and `tests/`.
2. `composer php-cs-fixer`: PHP CS Fixer with the Symfony rule set. It rewrites files in place and does not fail the build, so run it before you commit. `make cs` does a dry run that stops on the first violation.
3. `vendor/bin/phpunit --coverage-clover=coverage.xml`: the test suite.
4. `composer check-coverage`: 100% line coverage on the hand-written code in `src/`. Generated classes under `src/Data`, `src/Responses` and `src/Requests/V*` are excluded.

CI runs the quality gate on PHP 8.3, runs the tests again on PHP 8.5, and checks that the endpoint reference is up to date with `composer check-endpoint-docs`.

## Repository layout

| Path | Contents |
| --- | --- |
| `src/AccessTokenManager.php`, `src/ClientFactory.php`, `src/Request.php` | Hand-written runtime. |
| `src/Requests/V*/` | Generated request classes, one per Logic4 tag and API version. |
| `src/Responses/V*/`, `src/Data/V*/` | Generated response objects and nested objects. |
| `generator/` | The code generator and the endpoint reference generator. |
| `docs/` | Hand-written guides and the generated endpoint reference. |
| `tests/` | PHPUnit tests. |
| `.github/workflows/` | CI, the daily endpoint update and the QA beta pipeline. |

## Generating the client

The generator reads Logic4's Scalar documentation page to discover API versions, downloads the OpenAPI document of each version, and writes request, response and data classes. It regenerates major version 3 only; the constant `GENERATED_MAJOR_VERSION` in `generator/Generator.php` controls this. Older namespaces stay as they are.

```bash
make generate                       # inside Docker
composer generate-endpoints         # production documentation
composer generate-beta-endpoints    # QA documentation, always re-downloaded
```

Both Composer scripts run Rector and PHP CS Fixer on the generated code. `generate-endpoints` also regenerates the endpoint reference. Downloaded OpenAPI documents are cached as `logic4-api-*.json` in the repository root and are ignored by git.

### Endpoint reference

`docs/endpoints/` is generated by reflecting over the classes in `src/Requests`. It needs no network access:

```bash
composer generate-endpoint-docs     # rewrite docs/endpoints/
composer check-endpoint-docs        # exit 1 when docs/endpoints/ is out of date
```

Run the first command after any change to `src/Requests`. CI runs the second.

### Documentation snippets

Every ```` ```php ```` block in `README.md`, the other Markdown files in the root and `docs/*.md` is parsed by `tests/Feature/DocumentationSnippetsTest.php`. Keep examples syntactically complete; a snippet that would not compile fails the build.

## Automated workflows

| Workflow | Trigger | What it does |
| --- | --- | --- |
| `ci.yml` | Push to `master`, every pull request | Quality gate on PHP 8.3, tests on PHP 8.5, endpoint reference check. |
| `update-endpoints.yml` | Daily at 09:30 UTC, or manually | Runs `composer generate-endpoints` and opens a pull request on `feature/update-endpoints` when anything changed. |
| `beta-release.yml` | Daily at 08:00 UTC, or manually | Generates the client from Logic4's QA documentation. Scheduled runs only build, test and upload a candidate. |

### Beta releases

Publishing a beta needs a manual run of "Build Logic4 QA beta" from `master` with `publish` enabled and a semantic `base_version` such as `4.1.0`, or the `BETA_BASE_VERSION` repository variable. The run must be approved through the `beta-release` GitHub environment. It creates a tag such as `v4.1.0-beta.1`, marks the GitHub release as a prerelease, and attaches `beta-metadata.json` with the Logic4 QA build number.

The beta pipeline only accepts changes under `src/`. Do not add generation steps that write elsewhere to `generate-beta-endpoints`.

## Releasing

1. Make sure `master` is green and `CHANGELOG.md` has an entry for the version under "Unreleased".
2. Move the "Unreleased" entry to a version heading with the date and add the compare link at the bottom.
3. Tag the commit as `vX.Y.Z` and create a GitHub release with the same notes under "Added", "Changed", "Deprecated", "Removed" and "Fixed" headings.
4. Packagist picks the tag up automatically.

Breaking changes get a section in `UPGRADE.md`.

## Pull requests

- Keep hand-written changes and generated changes in separate commits where possible; it makes review much easier.
- Add or update tests for behaviour in `src/`. Coverage must stay at 100%.
- Follow the existing code style; `composer php-cs-fixer` fixes most of it.
- Describe which Logic4 endpoint or namespace a change affects.
